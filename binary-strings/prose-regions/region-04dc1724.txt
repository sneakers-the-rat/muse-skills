## Output Contract

Deliver each produced requested output as a preview link on its own line, description as separate prose, not on the link line:

```markdown
![<artifact-title>](sandbox://<project_dir>/<file_name>)
```

`<project_dir>` in the link is your contract's `project_dir` written
workspace-relative, with no `~` and no trailing slash: `workspace/your_files/<artifact-slug>`
for an ordinary artifact, and `workspace/goals/<goal-slug>/files/<artifact-slug>` for a goal's
document. Derive it from the contract; never assume `your_files`.

`<file_name>` is the user-facing output file. A create names it for the artifact in lowercase, hyphen-joined words (e.g. `book-club-handout.pdf`); an edit keeps the existing file's name and extension unless the user asked to rename or convert it; deck files keep the `<artifact-slug>` names their scripts write. The link is derived from the verified output path: UTF-8 percent-encode each path segment while keeping the `/` separators literal, so a space becomes `%20` and every other character, digits included, stays exactly as the file spells it. Do not shorten, normalize, or reconstruct the name from the artifact title or surrounding prose. An edited file may keep spaces:

```markdown
![Quarterly Sales Review](sandbox://<project_dir>/Quarterly%20Sales%20Review%20Q3%202026.xlsx)
```

blocks/spaces_builder/targets/static.md- Device-target wiring: the host picks the device in the URL fragment. If it's missing, add this script at the top of `<head>`, exactly as written:

  ```html
  <script id="hatch-space-target">
    (() => {
      const params = new URLSearchParams(location.hash.slice(1));
      const root = document.documentElement;
      if (params.get("hatch_target") === "tv") root.dataset.hatchTarget = "tv";
      const widget = params.get("hatch_view") === "widget";
      root.dataset.hatchView = widget ? "widget" : "app";
      if (widget) {
        root.dataset.hatchWidget = params.get("hatch_widget") || "default";
        root.dataset.hatchInstance = params.get("hatch_instance") || "";
        const sizes = ["small", "medium", "large", "watch", "watch_round"];
        root.dataset.hatchSize = sizes.includes(params.get("hatch_size")) ? params.get("hatch_size") : "small";
        const style = document.createElement("style");
        style.textContent = 'html[data-hatch-view="widget"], html[data-hatch-view="widget"] body { background: transparent; }';
        document.head.prepend(style);
      }
    })();
  </script>
  ```

  It sets `data-hatch-target`, `data-hatch-view`, `data-hatch-widget`, `data-hatch-instance`, and `data-hatch-size` on `<html>`, and makes a widget's page transparent by default; a later rule with the same selector overrides it. Style targets with selectors such as `html[data-hatch-target="tv"]` and `html[data-hatch-view="widget"]`; the phone and desktop page stays as it is. A widget is its own `<section>`, shown instead of the app, and declaring `widgets` is the one other `space.json` edit allowed.
