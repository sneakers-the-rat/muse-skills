peer.invite_createCreate a pairing invitation so the user can pair with someone and your Muses can talk and work together. `access` is the level the invitation offers, either Ask first (`restricted`) or Act freely (`trusted`). `recipient_name` is who the user said it's for, when they named the person. The runtime shows the user either an approval card or a button that opens pairing. When the user allows the card, the runtime shows them the link in this chat, and you don't see it. When a button is shown instead, the result says so, and the user creates and shares the invitation from that button.

peer.confirm_personConnect the user with the person in a pairing request that's waiting for the user to confirm who they are. The person is either someone who accepted one of the user's pairing invitations or the person whose invitation the user accepted. `person_name` is the name the user used for that person, or empty when they didn't name anyone. The runtime normally shows the user either an approval card naming the person or a button that opens pairing. Only when accepting the invitation also recorded confirmation of the inviter does this tool retry that consent with no new card or button. When several people are waiting, the result lists them. Names come from the other side and are self-reported. If the user turns down the approval card, the request stays waiting and the person isn't declined.
The name the owner used for the person in the waiting pairing request. Leave empty when they did not name anyone.Confirm the person in a pairing request waiting for the owner, after the owner approves it.

The runtime shows the user its own approval card. When several people are waiting, the result lists them. Names come from the other side and are self-reported.
Decline the person in a pairing request waiting for the owner, after the owner approves it.
