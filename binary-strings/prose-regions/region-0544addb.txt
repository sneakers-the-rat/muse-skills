Direct lookup for one exact Instagram, Facebook, or Threads post URL, including `threads.com/@user/post/...`, `threads.com/t/...`, `threads.net/@user/post/...`, and `threads.net/t/...` short links.

Set this when the user provides a specific post link and wants information about that exact post. Use `post_url` instead of translating the link into `semantic_queries`, and instead of opening the link in the browser.

Do not combine `post_url` with other fields.
Set ONLY if the user explicitly applies a platform constraint:
- Explicitly, such as "on Instagram", "from Facebook", "in Threads", or "IG only".
- Implicitly via platform references or shortnames in the request, such as "IG", "Insta", "FB", "on my Instagram feed", or "Threads post".

If the user does not imply a platform, OMIT this field and search all platforms.
Determines how search results are ranked.

- "informational" is the default (applied when omitted), and retrieves the most accurate results. For how-to, advice, tutorials, factual questions, reviews, comparisons, "best X", recipes, recommendations.
- "engagement" retrieves posts that have high engagement and are popular. For trending topics, opinions, "what are people saying", viral content, hot takes, debates, memes, reactions, community discussion, celebrity/gossip.
- "recency" progressively downranks older posts within relevance ranking (posts within 48 hours keep full weight; older tiers sink, down to 70% past three months). ONLY for time-critical breaking updates (live scores, "just happened", official announcements). Do not use this for general news queries — pair "informational" with `since` instead.
Filter by author's social relationship. Can be used with or without `semantic_queries`.

- "friend" - Mutual connections (IG mutual follows + FB friends). Trigger: "my friends".
- "followee" - People you follow. Trigger: "people I follow", "accounts I follow".
- "follower" - People who follow you. Trigger: "my followers".
- "all" - Default. Omit for default behavior.

Set whenever user mentions a social relationship. For pure browse with no topic, set this WITHOUT semantic_queries. For topical queries, set this WITH semantic_queries.
Search queries. The FIRST element is your primary query, used for ranking: a concise, specific phrase (3-8 words) capturing the core intent. Include key entities and proper nouns; prefer concrete terms ("Taylor Swift Eras Tour", not "popular concert tours").

Provide 2-4 additional queries targeting different facets of the topic. Each must retrieve a substantially different set of posts — no near-duplicate rephrasings. Break the topic into subtopics, stakeholders, or content types. Results from all queries are merged and ranked, with the first query boosted.

Do NOT duplicate values you are already passing in other fields: a name you put in `authors` (a hard FROM-filter), group names, platform names, temporal words, and content format words all belong to their own fields (authors, group_names, platform, since, content_type), and repeating them in queries hurts retrieval. The one deliberate exception: when a person is the query's SUBJECT, their name STAYS in the query (add them to key_celebrities as well — that field only boosts ranking; the query is what retrieves content about them).

Omit this field entirely when there is no specific search topic ("what are my friends up to"); never fill it with generic terms like "recent posts".
Filter to posts POSTED on or after this date: YYYY-MM-DD. Always past dates, never future; this filters when content was posted, not when events will occur.

Set for recency-sensitive queries, with the lookback matched to intent:
- breaking/trending → days
- news/updates → weeks
- seasonal/holiday → months
- time-bounded ("Q4 2023", "during [event]") → set both since and until

Omit for evergreen how-to questions.

When since is set, remove temporal words (today, recently, latest, trending, this week, breaking, current) from semantic_queries entirely — date filtering is handled by this field.
How many results the call returns (best-effort). Results from every semantic query are merged and ranked, and the summary carries the top N of that merged set, not N per query. Default 6; the maximum is 25 (higher values are clamped).

Raise it when a broad sweep genuinely needs more breadth than the default; leave it unset for a focused lookup.
Only return posts created on or before this date: YYYY-MM-DD. Always past dates, never future; this filters when content was posted, not when events will occur.

Set this only for historical date ranges ("Q4 2023", "during Connect 2022").

When until is set, remove temporal words (today, recently, latest, this week, current) from semantic_queries entirely — date filtering is handled by this field.
