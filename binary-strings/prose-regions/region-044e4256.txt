feed.update_draftUpdate fields of an existing feed draft as JSON, without matching or copying
the file's old text. Writers use `unit_index` (zero-based, default 0) in their
assigned draft. Editors use `candidate_id` from their slate, only for selected,
flagged candidates during repair. No file path is accepted.

Put all changes for one unit in one call, for example
`{"candidate_id":3,"changes":{"emoji":"🧫"}}`. Supply each changed field's
complete new value; arrays and objects replace the whole field. Omitted fields
and other units are preserved. JSON whitespace, key order, quotes and Unicode
escaping in the stored file do not affect matching. Use `muse.write` to create
the initial draft or selection file; use this tool for unit revisions.

During media, change only media or attachment. During sources, change body_md,
sources, time_sensitivity or act_by. During taste and editor repair, change
only copy: kicker, emoji, title, body_md, stats, why_did_i_see_this or
share_instructions where the assignment permits it. Remove redundant stats rows
with a replacement array (use [] to remove all rows); preserve every retained
figure and fact. Preserve every fact and address while polishing copy.
The editor never changes sources, media, attachment, subject or other metadata.

All fields are checked before the draft is replaced. Success returns a revision
and the updated field names. You may pass that revision as `expected_revision`
on a later update; a conflict returns the current unit and revision without
writing, so reconcile against those values. Do not guess file formatting or
retry an unchanged rejected call. Finish using `feed.finish_step` as assigned.
