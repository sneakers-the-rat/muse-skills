Use a hook to monitor a changing condition with a lightweight script that polls frequently, filters out routine results, and wakes an agent only when something relevant happens. Use a cron when time or cadence itself is the trigger.

A hook has two parts:

1. A Bash polling script ending in `.sh` under `~/hooks/scripts/`. Write it with `#!/usr/bin/env bash`, `set -euo pipefail`, and `source "$HATCH_HOOK_RUNTIME"`. It runs through the normal tracked shell executor with the same base command environment and proxy setup as an ordinary shell command, but without secrets or connector credentials. Use public endpoints or local data, bounded fetches such as `curl --fail --silent --show-error --max-time 10 ...`, and `jq` for JSON. Record useful observations with `log "observation" '{"price":251.20}'`. Every run must end with exactly one `silent "reason" '{"optional":"payload"}'` or `wake "reason" '{"optional":"payload"}'`. If a fetch is inconclusive, log the failure and stay silent. If a conclusive condition means no future poll is useful, call `disable_after_run` before the final `wake` or `silent`. Track state between polls under `~/hooks/state/`. `HATCH_HOOK_DRY_RUN` is `1` for dry runs and `0` otherwise; compare it explicitly to `1` before skipping or redirecting state writes. Dry runs do not isolate script-managed state.
2. An instruction for the worker agent launched after `wake`. The wake reason and payload arrive automatically as event data. Write the instruction so the worker reports what it found in its execute summary; do not instruct it to write a report file the user did not ask for under `workspace/goals/<goal-slug>/files/` or into `workspace/your_files/`.

To create a hook, write the script first, then use `add` with a short stable id, the script path, the worker instruction, and a polling interval. Omit delivery unless the user asked for another chat; it defaults to the chat where the hook was created. A new hook starts disabled, and `update` preserves its current enabled state. After adding or updating, use `dry_run` to test: it waits synchronously for the script and log append, reports the decision, and launches no agent. Fix and repeat `dry_run` until the fetch and decision work, then `enable` to start polling.
