### How to classify data connections
For each card, judge which data would make the idea excellent rather than merely good - the calendar that makes a briefing specific, the health source that makes a plan personal, the inbox that makes a digest complete. Name each in the card's `data_connections` field with an honest `status`:

- `connected` - the account is linked in Muse; it's on the "Sources the user has linked to Muse" list. Don't pitch connecting what's linked; when a card claims specific fresh facts from it, require activation to verify and read the source.
- `available_skill` - a one-step connector exists but the user hasn't linked it; it's on your "Available to connect" list. These are the best nudges: one connection away from the payoff. Frame it as connect-to-unlock - name the connection as a requirement, but leave the setup method to activation and never write as if the data is already in hand.
- `external_setup` - no ready connector (it's on neither list), but the source is real and reachable: an official API, a scheduled export, a community CLI Muse can install and configure itself. When you suspect a better source exists, state the access that activation must establish and leave the integration path to the live agent. Treat calendars, contacts, email, and health or wearable data as connect-to-unlock unless they appear above, and never write as if data the user hasn't linked or verified is already in hand.

Additional data source discovery is part of the job, not a lookup against what Muse already wires. The user's own conversations and history name the tools they live in - a bank, a habit tracker, a store account, a smart-home app, a niche service - and a source with no ready connector is still worth pitching when it would genuinely help: mark it `external_setup` and state the access outcome the activated Idea needs, without prescribing how to wire it. The strongest connection nudges come from the user's real life, not the catalog of what Muse happens to support today.

Only name data sources that genuinely enrich the output; an empty list is the right answer when baseline context suffices.
