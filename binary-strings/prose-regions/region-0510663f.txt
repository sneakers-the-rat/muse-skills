{daemon_feedbackRecord feedback on any itemRecords one explicit verdict (`feedback_up` / `feedback_down`), and optionally the user's own words on why, against any item. `entity_type` and `entity_id` are parameters and the type list is OPEN: any lower snake_case name (<=64 chars) is accepted and lands in the cross-entity store with no code change. `idea` and `feed_unit` have dedicated handling because they own storage that predates this endpoint. An unregistered type gets NO existence check, so an id matching nothing is a durable row rather than a 404, and its rows have no cleanup owner. Entity-specific context goes in `metadata` (`surface` everywhere; `lane` and the `anchor_kind`/`anchor_id` pair additionally recognized for `idea`); unrecognized keys are stored but never interpreted. NOT idempotent: every call appends a ledger row, and the latest submission replaces the stored verdict WHOLESALE including the reason, so re-submitting without a reason clears the previous one. Disable generic POST retry middleware for this route. `idea` submissions are equivalent to `POST /api/ideas/{id}/feedback`, which remains supported and writes the same rows; a `feedback_down` there also stops the card being served.
