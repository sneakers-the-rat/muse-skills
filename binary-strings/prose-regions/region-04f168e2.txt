## Sending Muse Mail

### Prepare the command

- Prepare each send or reply with `mail_task.prepare_action`. The runtime adds the stable provider key, so leave out `--in-response-to`, `--idempotency-key` and `--additional`.

```sh
/opt/hatch/bin/muse-mail messages reply <stored-message-id> --reply-mode sender --text '<body>'
/opt/hatch/bin/muse-mail messages send --to recipient@example.com --subject '<subject>' --text '<body>'
```

- Continue a thread with `messages reply`, even when the recipients repeat or <!-- personal-muse-only:start -->the user<!-- personal-muse-only:end --><!-- group-muse-only:start -->a member<!-- group-muse-only:end --> wants a new subject. `messages send` starts a new thread, and a `Re:` subject does not join an old one.

- Before replying, fetch the target again and check its `id`, `thread_id`, subject, `header_from`, direction and `recommended_handling`. Before preparing, check the mode, source, recipient roles, subject and thread against what the task authorizes.

- Use plain text unless <!-- personal-muse-only:start -->the user<!-- personal-muse-only:end --><!-- group-muse-only:start -->a member<!-- group-muse-only:end --> asked for HTML. There is no forward command, so to pass on a received email's content, write it into a new send or reply.

### Sign

- `~/workspace/muse-mail/preferences.md` holds durable email preferences <!-- personal-muse-only:start -->the user<!-- personal-muse-only:end --><!-- group-muse-only:start -->members<!-- group-muse-only:end --> explicitly asked for, such as the signing identity, tone, format and signature behavior. Read it before each send or reply when it exists, use the bundled default for any setting it lacks, and do not change it. A chat request's `preferences_file` says whether it exists. Report a requested preference change in your notification.

If a draft signs off with <!-- personal-muse-only:start -->the user's<!-- personal-muse-only:end --><!-- group-muse-only:start -->a member's<!-- group-muse-only:end --> name, delete that name unless <!-- personal-muse-only:start -->the user<!-- personal-muse-only:end --><!-- group-muse-only:start -->that member<!-- group-muse-only:end --> wrote the sign-off or asked to write or sign as themselves.

### Recipients

- Pass `--reply-mode` on every reply:
  - `sender` answers the received message's stored `From`.
