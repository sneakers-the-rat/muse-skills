DRIVE IT: This audit left a browser session open on the current build. Run the command in `probe.cli` exactly as returned; for another operation keep its `--socket` path and replace `observe` with `act`, `batch`, `viewport`, or `flag`. `reload` shows a rebuild. After a new migration, run a new audit instead. Use `batch` to run several steps in one call. It reads a JSON list of steps from stdin, and each step names a control by its visible label, for example `[{"op":"act","name":"Add item","action":"click"},{"op":"act","name":"Title","action":"fill","text":"Test"},{"op":"observe"}]`. Read a probe response from the top (verdict fields first, `aria` and `nodes` last) and narrow with `observe --find`; never slice the JSON line. Every observe and act returns a `screenshot_path`; `muse.read` the frame after an act that should have changed something, because the tree cannot show layout. On an act, `screenshot_changed: false` means the action did nothing visible; a silent no-op on a control that only touches this artifact's own origin is a defect, and each `batch` step is judged by its own frame. A control that depends on an external site does nothing under the lockdown, so driving it proves nothing. Check its target or captured request instead, keep the integration, and name the unverified handoff in `verification_notes`. A correct href alone does not prove a link works. A `flag` stays inside the probe session; a defect you could not fix goes in `web_artifacts.exit_build` `verification_notes`.

<!-- section: mobile_fit -->
MOBILE FIT: `envelope.mobile_layout.verdict` `"fail"` means the whole page scrolls sideways at phone width. Fix the element named in `widest_selector` with wrapping, stacking, `minmax(0, 1fr)`, or constrained media, never page-level horizontal scroll.

<!-- section: reachability -->
REACHABILITY: `envelope.unreachable_controls.mobile` lists controls a phone user cannot operate: `occluded` (something is painted over it; the occluder is named), `invisible` (effective opacity 0 or a hidden ancestor, and a phone has no hover to reveal it), or `clipped_off` (cut off by a scrollport that cannot reach it). This list is the only place such a control appears. Fix the layout and re-audit.

<!-- section: assets -->
ASSETS: `envelope.broken_assets` lists stylesheet, script, or font requests that failed with a real HTTP status, so every entry is this artifact's own defect, never the lockdown. When the assessment names where the artifact already has the file, fix the reference; otherwise add the file.

<!-- section: data_context -->
DATA: `assessment.scope` counts rendered sandbox rows separately from durable rows. <!-- section: sandbox_affordances -->
SANDBOX AFFORDANCES: `envelope.blocked_affordances` lists controls the sandboxed iframe silently breaks: `print` (drop the Print or Save-as-PDF button and make the layout print-clean), `dialog` (replace `alert`, `confirm`, and `prompt` with in-page UI), `self_url_share` (delete the copy-own-link button; the Muse shell owns sharing).
