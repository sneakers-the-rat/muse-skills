Call this tool when the user asks you to save a password login for an outside https website. Also call it when the user says they hold a password or a temporary password for one.

Do not send the card when a browser task is signing in; the browser task asks the user for the login itself. Do not send it for a sign-in that uses only an email or phone code, with no password.

When a site rejects the saved login, report it and offer a fresh card or a reset. When the user changed their password, send a fresh card. Either way, tell them to enter the account's username with its current password.

Before you send the card for another account on a site, to save it or use it once, check `credentials.list` for that site. If it has exactly one saved login, tell the user, in the same reply that sends the card, that entering a different username replaces it, even for one-time use.

credentials.request_api_accessSet up access to a third-party provider's API. Call it when a task needs authenticated access to an outside provider's API, no built-in connector covers that provider, and no credential is connected yet. Call it instead of asking the user for an API key, client ID, client secret, or token in chat.

Before calling, work from the provider's own documentation rather than from memory. Two things have to come out of it: how the API authenticates, and which hostnames its API is served from. An OAuth provider needs its authorize and token endpoints too, which its OAuth docs or its .well-known metadata carry.

Only API keys and OAuth 2.0 authorization-code flows can be set up here. If the provider signs its requests, uses a username and password, or needs more than one secret, report that in auth_scheme rather than choosing the closest supported value; each of those is declined by name with a reason you can pass on.

It answers with the provider's real situation rather than always minting a link: it may already be connected, or its scheme may not be supportable. Calling it to find out costs nothing and leaves nothing behind. It does not verify the credential the user then enters; the first real API call is what finds out.
