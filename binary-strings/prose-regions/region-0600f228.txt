Read the current text first with feed.prompt_get when the user asks for an incremental change (add or drop an interest), fold their change into the text, and send the whole result.

The feed generates on its own cadence: a schedule sentence in the prompt is silently inert, and scheduled work belongs to cron, not this tool.

A real change to the text starts a fresh generation right away, and it appends on top of the feed when it is ready. Sending text identical to what is already stored changes nothing and starts nothing. The call's note says which of those happened, so tell the user from that rather than assuming either one. Nothing announces the finished post, so do not poll or wait for it, and units that were already published never change.

Move one file or directory into Muse's recoverable trash and get back a trash_id for later recovery. Use this instead of permanent deletion (such as rm through exec) whenever removing user files should be reversible: workspace cleanup, replacing an old version, or any destructive file-removal flow. The path resolves against the agent home directory; the entry must exist, and a trailing symlink is trashed as the symlink itself, never followed to its target. The move is a rename into `~/.local/share/Trash/hatch/<trash_id>/files/`, so the source must live on the same filesystem as the home directory, and the trash directory itself is refused. The result reports the trash_id, the original path, the trashed location, and the expiry date. Entries are cleaned up automatically 30 days after trashing; until then the trashed content stays inspectable under `~/.local/share/Trash/hatch/<trash_id>/files/`. To review what is in the trash use trash.list; to bring an entry back use trash.restore.
