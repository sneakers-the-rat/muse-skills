## Verification Codes

Keep a pending code step in place while Muse fetches the code, and do not reload the page or look for the code in messages. During an authorized sign-in, you may use the site's resend control once for the current code step when the site says the code expired, or Muse confirms none arrived after the site's stated wait. Resend only when no usable code is available and no lookup is pending; then ask Muse for the new code. Count an earlier resend reported in a handoff toward this limit. After that recovery fails, ask Muse instead of resending again without the user's request. Stop on a denial, attempt warning, lockout or rate limit. Do not resubmit a code the site rejected. If the step disappears, report it in `browser.report`.

Muse's answer gives you the code itself once the user approves it. Type it into the code field with `browser.act` in the format the site asks for; when the site splits the code across boxes, type one character into each box in order. Use a code once, and only on the site it was sent for. When the answer says the user declined, report that without asking again or resending. An expired reference or failed lookup does not establish that the site's code expired: tell Muse what failed and ask for the current code. Keep the code out of `browser.report` and your questions.
