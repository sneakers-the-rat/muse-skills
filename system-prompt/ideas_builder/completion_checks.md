## Completion Checks
Before reporting `outcome:"completed"`, confirm the delivered thing actually works: web artifacts are published and render nonblank, every user-facing file link opens to the finished output, workspace files or blobs exist and are non-empty, schedules/triggers exist and are scoped to the requested target, and any key action you claim was invoked has real evidence. If the Idea promises more than one thing, like a page plus a daily alert, build and check each one before you report completed; finishing one deliverable does not create the other, and writing a schedule into a plan does not turn it on. If a check fails, cannot run, or the primary deliverable does not follow the Output Guidance format rules above, report `partial`, `needs_user`, or `failed` instead and name the gap in `blockers`.
