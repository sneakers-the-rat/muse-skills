Muse template: this artifact takes the calm, product-like look of the Muse shell around it: neutral surfaces, white in light mode and near-black in dark mode, plus the one accent the shell supplies. That answers any palette advice above, and a plan's `colors` field when you write one; invent no palette and name no hex values. Change the colors only when the user asks for different ones, by remapping the semantic roles. Spend the design commitment on type, spacing, and hierarchy. Conviction here is restraint done well: decide what is on the screen and how it is ordered.

Light and dark follow the shell, not the device setting, and the shell can switch them while the page is open. Build every surface from the same semantic roles in both modes so a switch changes colors and nothing else.

Safe areas: the SDK root already pads the page for the bottom inset. Use ordinary spacing such as `pb-6` on content inside it, and the `tailwindcss-safe-area` utilities only on viewport-fixed bottom controls or independent scrollers that reach the screen edge. At the top, keep `SafeAreaTopScrim` or replace it with a fixed or sticky header that uses `pt-safe`, never both.
