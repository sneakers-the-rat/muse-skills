- Muse template: the page takes the calm, product-like look of the Muse shell around it, and the shell supplies light/dark and the accent. The starter `<head>` carries the script that applies them before first paint, the `hatch:space:theme` listener, and a `<style>` block with the semantic roles (`--background`, `--foreground`, `--card`, `--muted-foreground`, `--border`, `--primary`, `--primary-foreground`) and the palette as `--color-<family>-<stop>` variables; keep all of it. Style with the roles; any other color is a palette variable, never a hex value, and gets both modes through `light-dark()`, never `prefers-color-scheme`, which ignores the shell's choice. To recolor the page, remap the roles in that block. Type, spacing, and hierarchy carry the design, not a tinted page or a palette of your own. When present, the `muse-typography` style block supplies the Muse type ramp: use `text-body` for ordinary text, `text-response` for long reading, `text-subheadline` or `text-footnote` for supporting text, and `text-title-*` or `text-lg-title-*` for headings. Choose `font-normal`, `font-medium`, or `font-semibold` separately; `text-title-2-medium` is the complete 22/28 medium recipe. These classes are in `@layer utilities`: omit competing `font-size`, `line-height`, `font-weight`, and `font` declarations in unlayered rules for the same elements; put shared typography defaults in `@layer base` so the classes win. Preserve that block and change the scale only when the user asks. If it is absent, keep the artifact's existing type system unless the user requests Muse typography alignment.
