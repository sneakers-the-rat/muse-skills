### Accent color and safe areas

By default the artifact follows the shell's accent: `--primary` in `client/src/globals.css` reads the host accent, so leave it alone. Only when the user explicitly asks this artifact for its own accent color, pin it there: set `--primary` to one palette family for both modes, for example `--primary: light-dark(var(--color-pink-700), var(--color-pink-400));`, and keep `--primary-foreground` readable on it. When the user asks to follow the shell accent again, restore `--primary` from `/opt/muse/assets/spaces/templates/space-ts-muse/client/src/globals.css`.

On phones, Muse shows an artifact inset below the system bars unless `space.json` sets `supportsSafeAreas: true`, which draws it edge to edge. Set it only when every element that touches a screen edge protects itself: the top bar is `Toolbar` or carries `pt-safe px-safe`, bottom navigation is `TabBar` or carries `pb-safe px-safe`, a side column is `Sidebar` or carries `pt-safe pb-safe ps-safe`, full-screen scroll areas other than the page end with `pb-safe`, and fixed or floating elements use the safe-area offset utilities (for example `bottom-safe-offset-4`) instead of fixed pixel offsets. ### App title and filler

A Muse artifact is an app shown inside Hatch, whose header already shows its name, so by default don't repeat that name as a page heading or a `Toolbar` title: a title names the current view or selection (the open note's title, "Archive"), or is left out so the actions stand alone. If the user asks for a header or logo, or shows one in a reference image, include it. Keep copy lean unless the user asks for more: leave out taglines, decorative or rhetorical headings, instruction or hint lines, counts or status lines that restate what is visible, and empty-state copy longer than one short line.

### Muse components

When `package.json` lists `@hatch/muse-ui`, import these from it instead of building your own: `Button` (`variant`, `size`), `IconButton` (requires a `label`), `Dialog`, `Menu` (with `Menu.Item`, `Menu.CheckboxItem`, `Menu.RadioGroup`), `Toolbar` with `Toolbar.Button` and `Toolbar.Back`, `TabBar` with `TabBar.Item`, and `Sidebar` in `Sidebar.Layout` with `Sidebar.Item` and `Sidebar.Toggle`. Back navigation uses `Toolbar.Back` (icon-only), never a text "Back" link or a hand-made arrow. A sidebar runs the full height on the start side with the `Toolbar` beside it, above the content column, never under a full-width toolbar. Pass icons as glyphs from `@space/icons` (`icon={HomeGlyph}`) with a `label`. Safe areas are built in, so these meet the `supportsSafeAreas` requirements: `Toolbar` pads for the top inset and replaces `SafeAreaTopScrim`, `TabBar` pads for the bottom inset and reserves its height, `Sidebar` pads the edges it touches, and dialogs and menus stay clear of both. If you write your own top bar or bottom navigation instead, give the top bar `pt-safe px-safe` and the bottom bar `pb-safe px-safe`. `Toolbar.Back`, `Sidebar.Toggle` and the `Dialog` close button have English default labels; when the artifact's interface is in another language, pass `label` (`closeLabel` on `Dialog`) in that language. For anything these don't cover, import unstyled Base UI parts from `@hatch/base-ui/<part>`, such as `import { Popover } from "@hatch/base-ui/popover"`.
