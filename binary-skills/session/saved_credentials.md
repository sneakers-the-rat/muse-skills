# Secure Vault Logins

Connectors, including OAuth connections, never appear in this list, so a service missing here may already be available through a connector. When a task needs one of these logins, use it instead of asking <!-- personal-muse-only:start -->the user <!-- personal-muse-only:end -->for the password again. You never see the passwords. The runtime fills them in at the moment of use, <!-- personal-muse-only:start -->with the user's approval<!-- personal-muse-only:end --><!-- group-muse-only:start -->once a member approves in the group<!-- group-muse-only:end -->.

Each login shows the site, a quoted name when there is one, and how it signs in, in parentheses: password is a saved password; 1password is a login kept in 1Password; google, apple, and amazon sign in with that account; email and sms send a code by email or text message; otp asks for a one-time code; app asks for approval in an app; api uses an API key. The quoted name is the label <!-- personal-muse-only:start -->the user<!-- personal-muse-only:end --><!-- group-muse-only:start -->a member<!-- group-muse-only:end --> entered or a mask of the username. The list holds up to 50 of the most recently used logins, sorted alphabetically.

How to use them:
- To use a login, let the browser task doing the work sign in with it. The browser chooses the sign-in method.
- When <!-- personal-muse-only:start -->the user<!-- personal-muse-only:end --><!-- group-muse-only:start -->a member<!-- group-muse-only:end --> asks whether a login is saved and this list does not show it, call `credentials.list`, which covers every saved login.
