proactivity.notify_userSave instructions for ordered proactive delivery turns, with a personal chat destination and relevant earlier user message for each result.
Queue one ordered batch of delivery instructions. Each entry runs as an ordinary agent turn after this private coordinator ends, one at a time. Those delivery turns write the user-facing replies.

Use `items` with the number in each result's `Item N` heading. Prefer the single strongest opportunity, with at most two across the batch, including grouped items. Choose none when nothing is worth the user's attention. Useful work, insight or delight can earn a message without urgency. Group related results when useful and assign each item only once.

The runtime adds one review of pending actions after the selected updates, so it can account for what they already communicated. You may supply reporting context or a different destination in one entry without `items`. `messages: []` queues only that review when needed. It applies the user's reporting preferences and may finish silently.

Keep `instructions` focused on the delivery's purpose, new findings and remaining work. The runtime attaches the original source blocks and exact presentation references for the assigned items or actions. Do not duplicate them. Include any additional evidence, file paths, IDs, builder instructions or authorization limits that delivery needs. A queued or unfinished result is not completed work.

Omit `chat_id` to deliver in this chat, including when the runtime routed this delivery to WhatsApp. Supply a verified ID for another active personal Muse chat only when the work belongs there. Other external-service chats, peer, group, archived and deleted chats are unsupported. The runtime tries the selected items’ saved reply references. If none fits the destination or another message gives better context, find a relevant user message with `muse.memory_search` and `chat.read_messages` and set its exact `reply_to_message_id`, even if it is old. Invalid or unavailable targets are omitted, and another prepared reference is used when valid. A message from another chat cannot be quoted here. For an action report, supply its reply reference in the optional entry without `items`. Leave it unset only when no suitable message can be recovered.

The result lists the saved deliveries and any omitted entries. Invalid optional reply metadata does not block delivery. Repeated sources merge in the same destination. Entries with invalid destinations, unknown sources or too many items are omitted without blocking other entries. Omitted work is not delivered. An omitted action review leaves its reports pending.

The first accepted batch fixes its entries, order, destinations and action claims. After an interrupted call, retry to recover that saved batch. A retry neither replaces it nor adds deliveries. If nothing was saved, correct any errors that still matter before retrying. Otherwise end with `muse.nothing_to_do` so delivery can begin. If there is nothing worth queuing and no action review is due, finish directly with `muse.nothing_to_do`.
