Active notifications surfaced by the system notification listener. Each entry has `app`, `app_package`, `title`, `body`, `sender`, `category` (one of msg, email, social, call, missed_call, other — `call` is a placed or in-progress call, `missed_call` is one the user missed; never treat them as the same thing), and `dedup_key` (a stable id for the same physical message across re-emissions — use it to avoid reporting a notification twice). In messaging notifications, `sender` identifies each message's author, including the user's own replies. `title` labels the notification or conversation, not necessarily the sender. For when it arrived use `timestamp_local` (the user's local wall-clock time), `timestamp_local_date` (their local calendar day), and `timestamp_weekday` (their local weekday name). `timestamp` is UTC and internal — NEVER show it to the user and never use it to compute the day, date, or weekday: it names the wrong day for notifications that arrived in the evening. Show the weekday using `timestamp_weekday` verbatim.

Place a phone call from the user's own phone, on their own number, with the user speaking. This is NOT the agent calling tool that talks to the recipient on the user's behalf — that one is for businesses. Prefer this whenever the user wants to speak themselves, and use it for personal contacts (family, friends, saved contacts, personal mobile numbers), which the agent calling tool does not handle. ALWAYS invoke this tool when the user asks to call a person — never claim a call was placed without invoking it. It dials directly when calling permission is granted and the app is in the foreground; when the app is backgrounded a tap-to-call notification is posted instead; and when calling permission is not granted a tappable calling card is shown so the user can place the call themselves.

Register a geofence so the device sends a proactive notification when the user arrives at or leaves a location. Use this when the user asks for location-based reminders (e.g. 'remind me when I get to the office', 'let me know when I leave home', 'notify me when I'm near the gym'). The geofence runs in the background with minimal battery impact and survives app backgrounding. IMPORTANT: Do NOT guess latitude/longitude coordinates for named places. Instead, provide the address and the device will geocode it to precise coordinates. You can provide either an address OR latitude/longitude. By default geofences are one-time (auto-removed after first trigger). IMPORTANT: Ask the user whether they want a one-time notification or ongoing monitoring before setting the geofence. Set persistent=true for ongoing monitoring. Returns a geofence ID that can be used with geofence.remove to cancel it.

Set a new reminder on the user's device. At the chosen time the reminder posts a high-priority notification (with sound) — distinct from alarms, which ring through the system clock app. If the user says 'alarm' or 'wake me', use alarm.set instead, even when the time is relative like 'in 10 minutes'. Use this for requests like 'Remind me to stretch in 2 hours', 'Remind me to take my medicine at 3pm', 'Remind me every weekday at 9am to stand up', or 'Remind me to call mom on May 15 at 9am' (supply date='2026-05-15' for future-dated reminders more than 24 hours away). For richer repeats, pass `frequency` ('DAILY', 'WEEKLY', 'MONTHLY', 'YEARLY') with an optional `interval` (e.g. frequency='DAILY', interval=3 for every 3 days). Bound a repeating reminder with `count` (total number of times) or `until` (ISO-8601 end date); for MONTHLY/YEARLY pass `date` as the start so the day-of-month is anchored. Always pass `reminders_json`, a JSON array string of reminder objects, even for one reminder. Each object must include `hour` and `minutes`; optional per-reminder fields are `message`, `days`, `date`, `frequency`, `interval`, `count`, `until`, and `timezone` (an IANA id like 'America/Los_Angeles'; defaults to the device time zone).
