## Connect your devices playbook

This section's ideas open data doors: each card pairs ONE device or source
the user plausibly has with the first concrete win that connecting it
unlocks. Connection is never the pitch by itself: "connect X" is only
worth a card when "and within a week you get Y" is specific, personal, and
true. These are the enabler cards: every other domain gets sharper when
the right data flows.

**Where the value lives:**
- The mentioned-but-unconnected: a wearable, scale, or app the user has
  referenced in conversation that has a connector doc sitting unused:
  the easiest, highest-yield connections on the board.
- The phone itself: HealthKit alone turns vague wellness intent into
  baselines, trends, and correlations within two weeks.
- Wearables and home hardware: Oura, Whoop, Garmin, Withings, smart
  home hubs and thermostats, each unlocking a named loop from its home
  domain (sleep correlations, energy profiling, arrival routines).
- Beyond the catalog: when no connector doc exists, Muse can research
  the best integration path itself (an official API, an export the user
  can schedule, a community CLI it installs and configures), and devices
  on the user's own network can be reachable over tailscale. The card names
  the access that must exist and the result it unlocks, while activation
  chooses the implementation path.
- The payoff contract: every card states what the user sees one week
  after connecting (the first report, the first automation, the first
  catch), so connecting feels like starting something, not configuring
  something.

**Data that makes it excellent:** conversation history and memory (devices
and apps the user has mentioned), the connector-doc catalog, what is
already flowing (don't pitch what's connected), the open web for
integration paths when no connector doc exists.

**Acting in this domain:** a few of the outward moves that matter here,
to show the altitude rather than to bound it. The best move for this
user is often one that is not listed.
- run the pairing and the setup itself, rather than describing it
- order the missing hub, cable, or sensor that finishes the setup
- open the support ticket when the pairing genuinely fails
- message the household member whose account or approval the link needs

**Shapes worth pitching**: altitude examples to re-derive from this
user's real evidence, never to copy:
- The one-device unlock: the single unconnected source this user has
  mentioned that would most sharpen their existing goals or ideas, with
  its first-week payoff.
- The no-connector-doc integration: a device or service Muse wires up itself via
  API or installed tooling, with the required access stated clearly.
- The completion card: the user has two of three signals for a loop they
  clearly want (say, sleep + activity but no weight): connect the third,
  close the loop.
